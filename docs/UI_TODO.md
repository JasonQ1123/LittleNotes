## 二、待修改（第二批：一致性）

> 2026-10-20 已完成：2.1 收敛为 `tokens.css` + `overrides.css`，旧绿色体系随 `style.css` / `sunshine.css` 一并删除；2.2 补全 `Source Han Serif SC` 回退但仍未自托管；2.3 按钮固定四档（primary / secondary / quiet / danger），退出登录降为 quiet；2.4 正文 32em、表单 640px；2.5 空态、加载、错误各收敛为一个组件；2.6 详情页右栏改为 sticky。逐条验证见 [UI 审计与验收](UI_AUDIT.md)。

### 2.1 把两套主题收敛成一层 token

现状：`style.css`（约 3,570 行）仍是最早的墨绿色体系，`sunshine.css`（约 870 行）整体覆盖为奶油色。结果是绿色残留在约定卡、统计填充、部分标题色；圆角混用 8/10/12/16/18/22；阴影两套；同一个「标题」在不同页面分别是宋体与黑体。

建议：把 `sunshine.css` 里散落的覆盖整理成 `--color-*`、`--radius-*`、`--space-*`、`--shadow-*`、`--text-*` 五组 token，删掉被完全覆盖的旧规则（预计可减 600–900 行），再按页面逐个回归截图。不要一次性重写，按「tokens → 通用组件 → 页面」三步走。

验收：全仓不再出现旧色值（`#738570`、`#a7b89b` 等）作为字面色；圆角只出现四档；三档宽度截图无回归。

### 2.2 标题字体跨平台不一致

现状：`--title-font` 为 `'Noto Serif SC', 'Songti SC', 'STSong', 'SimSun', serif`，没有加载任何 webfont。Windows 落到 SimSun，部分安卓落到系统默认衬线或黑体，文艺感在用户手机上可能消失。

建议二选一：

- 自托管子集化宋体：标题用字有限，可裁到 200 KB 内，注意记录标题是用户输入，子集需覆盖常用汉字（约 3,500 字）。
- 接受系统字体：补全 `'Source Han Serif SC', 'Noto Serif CJK SC'`，并把宋体限定在 ≥20px 的标题，正文保持系统黑体。

验收：Windows、iOS、Android 三端标题截图一致或差异可接受；首屏字体加载不阻塞（`font-display: swap`）。

### 2.3 按钮层级与危险操作

现状：主按钮在不同页面分别是珊瑚实心、描边、“text-button”；空间页「退出登录」与「修改昵称」同样式上下排列；详情页底部「我同意结束跟进」是描边按钮。

建议：固定四档 `primary / secondary / quiet / danger`，明确每档的使用场景；退出登录降为 quiet 或收进「账号安全」；破坏性操作统一 danger 且不与常用操作同级。

验收：全站按钮可归入四档，无第五种样式。

### 2.4 宽屏阅读宽度

现状：1440 下正文行宽接近 1,100px，回访表单输入框拉满整行，长段落阅读吃力。

建议：正文卡片 `max-width: 720px`，表单 `640px`，超出部分留给 sticky 侧栏或留白；列表页保持全宽。

验收：1440 下正文行宽不超过 80 个汉字。

### 2.5 空状态、加载态、错误态统一

现状：有的页面用 `Loading…` 文字，有的用 spinner，有的用 `EmptyState` 组件；错误提示有的是 notice，有的是 toast。

建议：三种状态各收敛为一个组件，规定使用场景（页面级 / 区块级 / 操作级）。

### 2.6 详情页左右栏高度不齐

现状：`story` 标签左侧卡片按内容高度，右侧栏更高，底部留下约 250px 空白（第一批已把空白从卡片内移到卡片外）。

建议：把「以前，是不是也遇到过」移到右栏，或让左栏吸底对齐；也可在桌面把右栏做成 sticky。

## 三、待修改（第三批：体验与美化）

> 2026-10-20 已完成：3.1 移动端首屏（hero 压成引言条，390×844 下首条待办 top=690px）；3.2 首页文案改为中性的「有些话，先写下来。有些约定，一起记得。」；3.4 详情页标题下方新增「接下来的一步」行动条；3.6 触控目标 44px、焦点环、占位符对比度、`prefers-reduced-motion`。
> 仍未做：3.3 统计页信息设计（坐标轴、按周分桶、分类排序后的占比标注）、3.5 微交互、3.7 品牌资产、3.8 空态插画。

### 3.1 移动端首屏

现状：首页 hero 占约 700px，待办列表要滚动一屏才出现；而待办才是每天打开的理由。

建议：移动端隐藏插画、压缩文案，hero 降级为一条问候 + 三个计数；或把待办提到 hero 上方。

验收：390×844 首屏内至少看到第一条待办。

### 3.2 首页 hero 文案

现状：「和好以后，也记得一起向前。」但用户打开首页时常常正在矛盾中，「和好以后」预设了结果。

建议：改为中性、指向行动的文案，例如「有些话，先写下来；有些约定，一起记得。」（与登录页一致）。

### 3.3 统计页重构

现状：柱状图无坐标轴与刻度；分类条固定顺序；回访部分用圆点表达分布。

建议：

- 柱状图补 y 轴与基线，或改为按周分桶；
- 分类条按数量排序，标注占比；
- 回访改为双人对比条 + 时间趋势；
- 「也许值得再聊聊的事」改为卡片流，补充最近一次回访日期。

### 3.4 详情页行动条

现状：标题、状态、标签、四个 tab 的信息量接近，用户不清楚「现在该做什么」。

建议：在标题下方加一条行动提示（待确认 / 待补充视角 / 待回访 / 待归档），点击直达对应 tab。

### 3.5 微交互

建议：tab 下划线滑动过渡、卡片 hover 轻微抬升、按钮按压反馈、toast 进出、列表渐入；统一 `transition` 时长与缓动，并尊重 `prefers-reduced-motion`。

### 3.6 可访问性与触控细节

建议：检查占位符对比度（当前偏浅）、禁用态对比度、触控目标 ≥44px、焦点环在奶油底上的可见度；补充键盘操作说明。

### 3.7 品牌资产

建议：补 `apple-touch-icon`、`og:image`（邀请链接分享时没有预览图）、`manifest.webmanifest`；`og:title/description` 与页面文案保持一致。

### 3.8 空状态插画

建议：为空空间、无记录、无约定、无回访分别准备一张手绘感小插画，替换当前统一的图标 + 文案，强化手帐气质。

## 四、验证方式

截图与无障碍检查（本地临时脚本，不入库）：

```powershell
pnpm exec playwright test --config .cache/visual/playwright.visual.config.ts
```

- 截图输出在 `.cache/visual/shots/{desktop,mobile}/`，检查结果在 `audit-*.json`（空数组表示无问题）。
- 手机长截图里底部导航出现在页面中部，是 `position:fixed` 在整页截图中的渲染假象，不是布局缺陷。
- 全量 `pnpm test:e2e` 已有一个既有问题：登录/注册限流为进程内 40 次 / 15 分钟 / IP，整套用例连续跑两轮会触发 429。跑回归时建议按文件分组执行，或先修复限流隔离（见工程待办）。
