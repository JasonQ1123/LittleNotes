# 经验记录

本文件只记录非显而易见的失败、根因和做法；通用编程知识、一次性流水账不写。

格式见 [开发流程](DEVELOPMENT.md) 附录 D。每条包含：日期、场景、症状、根因、做法、预防。

## CI 镜像来源可以与生产分开配置

- 日期：2026-10-27
- 场景：PR #3 的容器检查在 `deploy.sh` 构建初期失败。
- 症状：读取 ECR Public 的 `node:24-bookworm-slim` 镜像信息时返回 `429 Too Many Requests - Data limit exceeded`，尚未执行应用冒烟。
- 根因：CI 只提前缓存了 PostgreSQL，Dockerfile 的 Node 和 Caddy 基础镜像仍需从 ECR 获取；镜像仓库限流与应用代码无关。
- 做法：仅在 CI 工作区把 Dockerfile 的镜像前缀替换为 Docker Hub 官方镜像地址；生产继续使用部署环境可访问的 ECR 官方镜像。
- 预防：容器检查失败先区分仓库拉取、构建、启动和业务断言阶段；不要用修改生产镜像配置解决 CI 专属网络问题。

## 正式域名变更需要同步冒烟请求来源

- 日期：2026-10-27
- 场景：CI 的生产容器启动成功，但部署冒烟第一次登录就失败。
- 症状：`POST /api/auth/login` 返回 403。
- 根因：冒烟固定发送 `Origin: https://littlenotes.cn`，而实际允许来源已经是 `https://web.littlenotes.cn`；API 的来源校验按设计拒绝请求。
- 做法：同步冒烟的 Origin 与 HTTPS 配置校验域名，保持来源检查规则。
- 预防：域名切换时同时检查部署默认值、CI 请求头、Caddy 验证参数和邀请入口。

## 全量浏览器回归需要独立的登录限额

- 日期：2026-10-27
- 场景：发布前在同一个 E2E API 进程上顺序运行桌面和手机的 26 项浏览器用例。
- 症状：前 20 项通过，随后注册返回 429，部分页面停在登录页，最终 4 项失败。
- 根因：登录和注册共用同来源 15 分钟 40 次的计数；桌面和手机用例累计消耗同一个来源的额度，失败与被测空间流程无关。
- 做法：`AuthService` 支持正整数配置 `AUTH_LIMIT_PER_15M`，默认 40；`scripts/e2e-api.mjs` 仅在独立测试进程中设为 10000。新增默认边界、配置上限和非法值测试，持久化限流另按 TODO S5 推进。
- 预防：发布验证必须运行完整测试集合；共享进程中的限流、邮件额度等资源要有独立测试配置，不能只用分组通过代替全量通过。

## 无语言标记的接口片段会被 Prettier 按 TS 重排

- 日期：2026-10-20
- 场景：给 `docs/WECHAT_MINIPROGRAM_MIGRATION.md` 加格式门禁时试跑 `prettier --check`。
- 症状：`POST /api/auth/wechat/login` 被改写成 `POST / api / auth / wechat / login;`，请求体也被展开成 TS 对象。
- 根因：代码块被标记或推断为 `ts`，Prettier 按 TypeScript 解析；内容本身不是合法 TS。
- 做法：在 `.prettierignore` 排除该迁移草稿；接口片段应使用 `text` 或 `http` 语言标记。
- 预防：文档里的伪代码、接口示例统一用 `text` 代码块；格式检查改动语义时先停下来核对。

## 原生 select 在 140% 缩放下的文字会被裁掉下半截

- 日期：2026-10-20
- 场景：全站重设计后，用户在 Windows 140% 缩放的 1825×923 窗口里看到筛选栏「全部分类 / 全部状态」只剩上半截字。
- 症状：`<select>` 的文字被一条水平线切掉底部；同样字号同样内边距的 `<div>` 渲染正常。DPR 1 时不明显，1.4 时稳定复现。
- 根因：Chrome 对 select 内部行盒的高度有额外要求，固定 `height: 40px` 且上下内边距较小时，文字会溢出内容盒并被 `overflow: clip` 裁切；改 `line-height`、`appearance: none` 都无效。
- 做法：`appearance: none` + 自绘 chevron，模板不再依赖原生箭头；select 改为 `height: auto`、上下内边距 12px（自然高约 47px），并把同组输入框、按钮统一到 46px，保证一行控件等高。
- 预防：不要给 select 写死高度；任何「文字被横切」的现象先用 1.4 倍 DPR 复现，再对比同款 div 的渲染，能快速判断是控件还是布局问题。

## 用 flex 子项拼连续基线时，空标签会把基线拆成一段一段

- 日期：2026-10-20
- 场景：统计页柱状图的基线由每列 `.chart-track` 的 `border-bottom` 拼成；自定义区间按月分桶后，用户看到基线断成错落的小段。
- 症状：同一排柱子的基线高低不一，像"爆炸"；改变区间跨度（标签稀疏程度）时更明显。
- 根因：标签稀疏时部分列渲染空 `<small>`，空元素作为 flex 子项高度为 0，这些列的轨道 `flex: 1` 多占了 19px，`border-bottom` 因此和别人不在同一水平线上。
- 做法：给标签固定行高（`height/line-height: 16px`），保证每列轨道等高；基线就回到一条直线。
- 预防：任何"每个子项各画一段边框、拼成一条线"的布局，先确认所有子项高度一致；空内容也要占位，或改用单个父级伪元素画线。
