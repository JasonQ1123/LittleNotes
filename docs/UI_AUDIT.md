# 小纸条 · UI 层级审计与验收

更新日期：2026-10-20。审计对象是改造前的全站（13 条路由、15 个组件、两套 CSS），方法按 Refactoring UI 的 Workflow D：按「层级 → 布局间距 → 排版 → 颜色 → 深度 → 图片 → 收尾」固定顺序扫一遍，再按 Workflow C 逐项改造。视觉规范见 [DESIGN.md](DESIGN.md)。

证据来源：`.cache/visual/shots/` 的 1440 / 390 两档整站截图、axe WCAG 2A/2AA 扫描、对 `style.css` 与 `sunshine.css` 的脚本统计、对 323 个色值的实测对比度。

## 二、刻意没做的

- 没有换掉宋体标题：它是品牌语气的一部分，换成黑体会让「纸条」变成通用后台。
- 没有引入 UI 组件库，也没有把界面改成 Tailwind 工具类：项目里的 Tailwind 只提供 preflight，混用会让层级再次失控。
- 没有做暗色模式（排入下一轮）、没有自托管字体（已决定不做，见 [UI_TODO](UI_TODO.md) 第四节）、没有新增空态插画（P2-4）。
- 没有改后端接口、数据模型、权限与业务文案；e2e 依赖的可访问名称保持原样。

## 四、遗留与下一步

- 全量 `pnpm test:e2e` 仍受登录限流影响：同一 IP 连续跑两轮会 429，属于既有问题，建议按文件分组执行。
- 统计页的柱状图仍没有 y 轴刻度与按周分桶，属于信息设计问题而不是样式问题，见 UI_TODO 3.3。
- 详情页「结束跟进」在行动条与页尾各出现一次：行动条负责引导，页尾按钮负责确认，文案不同但意图相同，后续可合并为一个入口。
