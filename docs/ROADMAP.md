## 2. 当前实现基线与约束

- 账号已有用户名、昵称、密码哈希、当前空间关联和可空头像存储键 `avatarKey`，没有邮箱、手机号或找回凭证字段。
- 密码使用 Argon2id 哈希；登录使用数据库会话和 HttpOnly Cookie，已有会话通常有效七天。
- 已实现当前密码校验、修改密码与全部本人会话撤销；改密限流存储于 `PasswordChangeLimit`，密码找回及重置凭证仍未实现。
- 新注册和修改时的新密码要求 8–32 位，必须同时包含英文字母和数字；登录及当前密码验证保留旧规则，兼容已有账号。
- 每人最多加入一个当前空间，每个空间最多两人。目前只有创建、邀请、接受邀请和撤销邀请，没有退出或关闭功能。
- 当前通过 `User.spaceId` 和 `Space.members` 表示成员关系，没有历史成员记录。
- 纸条列表、约定、回访和统计依赖当前空间及成员关系，增加历史空间不能只改空间设置页面。
- 昵称编辑、头像上传与恢复默认已实现；共用头像组件覆盖导航、空间成员、视角、回访及纸条详情，无头像或加载失败时显示昵称首字。
- 本地 SQLite 与服务器 PostgreSQL 有独立迁移历史，新增模型和字段需要同时准备增量迁移。
- 当前 Caddy 对 `/api/*` 的请求体限制仍为 256 KB；浏览器先裁剪压缩，头像文件上传上限为 192 KiB，无需提高代理限制。
- 头像使用服务器持久目录，并随数据库成套备份；目前读取权限仅覆盖本人和当前同空间成员，尚无历史空间身份快照。

代码依据：`apps/api/prisma/schema.prisma`、`apps/api/src/auth.ts`、`profiles.ts`、`spaces.ts`、`records.ts`、`agreements.ts`、`dashboard.ts`、`apps/web/src/components/ProfileSettings.vue`、`AvatarEditor.vue`、`UserAvatar.vue`、`apps/web/src/views/SpacePage.vue`、`apps/web/src/types.ts` 和 `deploy/Caddyfile`。部署与恢复步骤见 [部署说明](../deploy/README.md)。

## 3. R001：空间解除绑定与关闭

### 产品方案建议

入口放在“我们的空间 → 空间设置 → 解除绑定 / 关闭空间”。确认页面说明操作结果，并要求重新验证本人身份，避免误操作。

建议将结束绑定与永久删除数据作为不同操作：结束绑定先终止共同使用，旧数据如何长期保留或删除另行确定。

建议的首版规则：

1. 已有两位成员时，任意一方可以主动结束绑定，无需等待对方批准；这是待确认的建议。
2. 操作成功后，双方均解除当前空间关联，旧空间转为已关闭，两人分别可以创建或加入新的空间。
3. 已关闭空间不再接受新成员，原邀请全部失效，不能把新伴侣加入旧空间。
4. 原成员可以从“历史空间”查看原本有权限看到的内容；新伴侣无法访问旧空间。
5. 已分享内容只读保留；私密草稿和未发布视角仍仅本人可见，解绑不会将其自动公开。
6. 旧空间停止产生待办、约定确认和回访提醒，但保留原业务状态用于回顾，不批量改写纸条的归档状态。
7. 双方收到中性的站内状态提示，例如“共同空间已关闭”；不要求填写或向对方公开解除原因。
8. 尚未邀请他人加入的单人空间，也可由本人关闭并保留自己的历史内容。

“解除绑定”暂拟用于双人空间，“关闭空间”用于描述空间结果及单人空间操作。是否需要两个独立按钮和不同效果，待用户决定。

### 历史数据与身份展示

建议关闭时保存历史成员的展示信息，避免未来修改昵称或头像后，持续向前伴侣暴露新的个人资料。历史头像是否保留、保留多久，需要与头像清理策略一起确定；首版也可只保留昵称快照和默认头像。

本方案暂不包含自动清空共同记录、导出、账号注销或复合后恢复旧空间。这些作为后续独立需求讨论；如果允许恢复，建议要求原双方重新确认，且不能与新的绑定冲突。

### 实施思路

- 为 `Space` 增加状态、关闭时间和操作人记录，具体字段名称在开发设计时确定。
- 增加历史成员表，例如 `SpaceMembership`，记录加入、结束时间和必要的显示信息；保留 `User.spaceId` 作为当前空间指针，并明确历史表与该指针的一致性约束。
- 迁移时先为现有空间补齐成员历史，再启用解绑功能，防止清除当前关联后失去历史权限依据。
- 提供结束绑定、历史空间列表与历史空间详情接口；路径暂拟为 `POST /api/spaces/:id/close`、`GET /api/spaces/history`。
- 在同一事务内重新读取空间状态及成员，完成关闭、解除双方关联、撤销邀请并记录操作；重复请求返回一致结果。
- 所有写入路径，包括新建纸条、视角、约定、确认、回访、关联、和好标记和归档，都检查空间仍开放以及当前成员身份。检查与写入处于同一事务，覆盖正在进行的请求与关闭操作的竞争。
- 接受邀请、重新配对与关闭必须执行一致的并发约束，确保一人最多一个当前空间、关闭空间不会接受第三人。
- 将历史读取与当前空间写入的权限分开处理，继续逐项过滤私密数据。关联记录、搜索和统计也必须遵循对应空间权限。
- 前端关闭成功后刷新会话与当前空间；另一方在下次访问或操作时同步状态。是否需要实时通知留作后续体验选项。

### 验收重点

- 任意一方执行后，双方都可以开始新的空间，旧邀请失效。
- 新伴侣即使持有旧纸条链接，也不能查看旧记录。
- 旧成员仍不能看到对方未分享的草稿和视角。
- 同时关闭、关闭与接受邀请、关闭与提交记录等竞争不会留下错误绑定或继续写入旧空间。
- 旧空间不再进入当前待办，刷新、重登与服务器重启后状态保持一致。

### 待确认

- 是否接受任意一方单独解除绑定？
- 解绑后双方是否继续拥有旧共享内容的只读权限，还是需要更严格的隐藏规则？
- “关闭”是否还需要永久删除能力？若需要，删除对象、双方同意规则、保留期与备份淘汰应另行明确。
- 历史空间是否长期保留，以及是否允许恢复。

## 4. R002：修改密码

状态：已按用户要求完成本地实现和自动化验证，待用户验收和生产交付。

### 已实现的交互

- 在“我们的空间 → 账号安全 → 修改密码”输入当前密码、新密码和确认新密码；即使没有创建空间也可以操作。三个输入框分别支持显示 / 隐藏密码。
- 已确认：新注册密码、修改时的新密码及确认新密码统一为 8–32 位，必须同时包含英文字母（A–Z / a–z）与数字（0–9），可额外包含符号，不自动删除首尾空格。新密码必须与当前密码不同，两次新密码需一致。
- 已确认：已有账号无须更改原密码，数据库中的旧密码哈希保持不变；登录及“当前密码”校验继续接受原有 8–128 位规则，不要求字母与数字组合。
- 成功后撤销本人所有设备的会话，清除当前 Cookie 和前端会话状态，返回登录页并提示使用新密码；其他账号不受影响。
- 当前密码错误、输入不一致或服务器失败时保留编辑界面供重试；提交中禁用重复操作，取消或关闭清空本次输入。
- 其他设备下次请求时识别登录失效并返回登录页。找回密码尚未实现，本轮未添加不可用的找回入口。

### 实际技术方案

- 已新增 `POST /api/auth/password/change`，接收 `currentPassword`、`newPassword`、`confirmPassword`，成功返回 `{ ok: true }`；仅允许登录用户修改本人密码。
- 服务端独立验证长度、确认密码与当前密码，使用 Argon2id 生成新哈希。密码更新和删除本人全部会话在同一事务完成，任一步失败均回滚。
- 注册与登录的密码 DTO 分别校验；注册、新密码及确认新密码共用新的服务端规则，前端注册与改密表单同步限制并显示提示。本次密码规则调整不新增数据库迁移。
- 在最终事务内重新确认提交所用会话仍有效，并以旧密码哈希为条件更新。登录签发会话也使用条件写入锁定已验证哈希，避免已验证旧密码的在途请求在改密后建立会话；并发改密最多一个成功。
- 增加 `PasswordChangeLimit` 表：通过格式及一致性校验的提交，每 15 分钟每账号最多 5 次、同来源 IP 最多 40 次；超限返回 429。计数在数据库事务中更新，可跨 API 实例和服务重启保留，到期后清理；来源使用哈希存储，不保存原始 IP。
- 错误当前密码及参数返回 400，登录失效返回 401，未受信任的跨源写入返回 403。接口响应不包含密码、密码哈希或内部会话凭证。
- SQLite 与 PostgreSQL 均提供 `20260906010000_password_change_limit` 增量迁移。迁移只新增限流表，不重置已有密码或会话；升级步骤已补入 [部署说明](../deploy/README.md)。

### 后续衔接

R003 引入密码重置凭证后，需要把未使用凭证的撤销纳入改密事务，复用当前会话签发与密码变更的并发保护；重置时的新密码也应采用当前 8–32 位字母与数字组合规则。本轮不包含邮箱绑定、密码找回或审计事件查询页面。

## 5. R003：找回密码

### 方案调整记录（2026-09-06）

- 此前已讨论采用阿里云短信、中国大陆 +86 手机号；用户反馈目前个人资质无法满足短信服务开通要求，本项目暂缓短信方案，改评估邮箱或密保问题。
- 此前已确定新旧账号均须验证找回渠道后才能使用、一个渠道对应一个账号，换绑使用当前密码与新渠道验证。邮箱方案默认沿用这些约束，具体邮件验证方式尚未最终确定。
- 建议采用邮箱验证码，邮件重置链接作为备选。密保答案可能被猜中、从个人信息推断，或被伴侣知晓，不建议将密保问题作为单独的重置凭据；一次性恢复码可作为后续独立备选需求，本轮不默认增加。

### 产品方案建议

建议首版采用“已验证邮箱 + 邮箱验证码”，也可选择一次性重置链接。当前没有邮箱或找回凭证，需先补充邮箱绑定和验证；短信暂缓。

推荐流程：登录页点击“忘记密码” → 输入已绑定邮箱 → 收到并输入验证码 → 设置新密码 → 回到登录页。新密码执行现有 8–32 位、同时包含英文字母和数字的规则，重置成功后撤销全部会话。

按此前的强制绑定要求，新用户验证邮箱后完成注册；旧用户在登录后进入绑定页面，验证完成后才能使用空间，后端同时限制未绑定账号的业务访问。一个邮箱只绑定一个账号，邮箱不向伴侣公开。没有绑定有效找回渠道的旧账号，不能只凭用户名、昵称或伴侣确认自动重置密码；未配置渠道且已经忘记密码的存量账号如何处理，需另定支持规则。

### 实施思路

- 为用户增加规范化邮箱和验证时间；待验证邮箱单独存放，验证完成后才启用找回能力。
- 邮箱绑定或变更要求验证当前密码，并验证新邮箱；旧邮箱在新邮箱验证成功前继续有效。原密码仍兼容旧规则，换绑成功后撤销全部会话及未使用的找回凭证。
- 增加邮箱验证及密码重置凭证，记录用途、用户、到期时间、错误次数和消费时间，避免不同用途混用。短验证码使用服务器密钥计算 HMAC 摘要；高熵重置链接令牌保存哈希，不记录明文验证码或令牌。
- 验证码或重置链接均需设置有效期、一次性消费及失败次数限制。若选择链接方式，建议约 20 分钟有效；GET 打开链接只展示页面，确认新密码的 POST 请求才消费凭证，避免邮件扫描器提前消耗链接。具体发送形式及参数在方案确认后确定。
- 申请找回时，对存在与不存在的邮箱返回相同提示，并控制响应差异；按邮箱和来源限制发送与验证频率。
- 成功重置时，在同一事务中消费凭证、更新密码、撤销全部旧会话及其他未使用重置令牌，覆盖重复提交与并发登录。
- 邮件链接只使用配置好的正式站点来源，不从请求头任意拼接。重置页避免第三方资源泄露令牌，代理和应用日志不记录令牌值。
- 先验证个人账号可用的邮件服务或现有邮箱 SMTP 是否支持该用途，再确定服务商。确认授权配置、发送配额和验证码邮件的实际投递情况；使用自有发信域名时准备域名验证及相关 DNS 配置，不能直接假设短信资质问题在邮件服务中不存在。
- 完成真实收信验证后再上线强制邮箱绑定，避免旧用户被卡在无法完成的绑定页面。
- 为发送记录设计持久状态或发件队列，限流状态覆盖服务重启和多实例，不能只依赖当前进程内计数。

### 验收重点与待确认

- 验证过期、重复消费、请求过频、邮件发送失败、邮箱变更，以及重置后旧密码和旧会话全部失效。
- 待确认：最终采用邮箱验证码还是重置链接，以及可用的邮件发送服务；密保问题暂不纳入推荐方案。

## 6. R004：修改个人头像

状态：已完成本地实现与自动化验证，用户于 2026-09-06 确认验收通过，待生产交付。

### 已实现的交互

- 在“我们的空间 → 我的小名片”选择更换头像，支持鼠标或触摸拖动、滑块缩放、方向键移动及圆形预览，保存后更新头像。
- 支持 JPEG、PNG、WebP 静态原图，最大 5 MiB、2400 万像素；不支持 SVG 和动画图片。
- 浏览器裁剪生成 256×256 WebP，上传文件不超过 192 KiB。取消时保留原头像；上传失败保留编辑界面和错误提示，方便重试。
- 恢复默认头像需要确认，恢复后显示昵称的首个 Unicode 字符；无头像或图片加载失败时也使用此回退方式。
- 保存后同步当前会话及当前空间成员数据；另一方或其他设备刷新后看到新头像。

### 实际技术方案

- `User` 增加可空字段 `avatarKey`；用户及成员响应提供 `avatarUrl: string | null`，不直接提供内部存储键字段。SQLite 与 PostgreSQL 均已新增 `20260906000000_user_avatar` 增量迁移。
- `PUT /api/users/me/avatar` 接收 multipart 字段 `file`；`DELETE /api/users/me/avatar` 恢复默认，重复调用结果一致。
- 服务端使用 Sharp 重新校验实际格式、动画、解码结果和像素上限（上传图总像素不超过 1,048,576），重新编码为 256×256 WebP 并移除 EXIF 元数据。
- `GET /api/users/:id/avatar` 返回 WebP，仅本人或当前同一非空空间的成员可读取。未登录返回 401，无权限或无头像返回 404。
- 头像地址带版本标识，响应使用 `Cache-Control: private, no-store`；各展示位置复用 `UserAvatar.vue`。
- Caddy 保持现有 256 KB 请求体限制，客户端及服务端共同限制裁剪后文件大小。

### 已确认的存储与备份

- 首版采用服务器持久目录。本地默认为 `apps/api/uploads/avatars`；生产宿主机 `/opt/littlenotes/uploads/avatars` 挂载到容器 `/app/uploads/avatars`，可通过 `AVATAR_STORAGE_DIR` 配置应用读取目录。
- `deploy/prepare-uploads.sh` 创建目录并设置 API 使用的 UID/GID 1000 写入权限；上传目录排除在 Git 和 Docker 构建上下文之外。
- 文件使用随机、不可变的 `.webp` 名称。先写新文件，再更新数据库；数据库更新失败时删除新文件并保留原头像。
- `deploy/backup.sh` 先备份数据库，再归档头像，生成配套的 `.dump`、`.dump.avatars.tar.gz` 与 `.dump.sha256`，备份组保留约 14 天。
- 替换或恢复默认后，旧文件延迟保留；仅在成套备份成功后，清理已无当前用户引用且超过 24 小时的旧文件。
- 恢复检查脚本兼容旧数据库单文件备份，并支持新备份组的校验和检查、解压及头像引用检查。具体操作见 [部署说明](../deploy/README.md)。
