# 空间解绑、关闭与限时恢复

状态：2026-09-07 已实现，待生产部署。当前线上版本仍以 README 的生产交付记录为准。

## 使用规则

- “我们的空间 → 空间设置”：双人空间任意一方验证当前密码后关闭，单人空间由本人关闭。不要求填写原因，不要求对方批准，不退出账号。
- 关闭立即解除全部当前成员绑定，撤销旧邀请。原成员可以创建或加入其他空间。
- 从关闭时刻起保留 30×24 小时；共享记录、本人的私密草稿、未发布视角均不可读写，不进入待办、搜索、约定和统计。
- “已关闭的空间”只展示名称、关闭时成员昵称、关闭时间、删除截止时间及恢复申请；不展示旧内容，也不展示对方后续头像、昵称、邮箱或新空间。
- 双人空间必须原双方都没有当前空间：一方验证密码申请，另一方验证密码明确同意。申请最长有效 48 小时，且不超过空间删除截止；重复申请不会刷新期限。
- 发起人可撤回，对方可拒绝；失效后可重新申请。相互发起申请不会自动恢复。任一原成员新建、加入或恢复其他空间时，其待处理申请失效；发起人认证版本变化后旧申请也失效。
- 原单人空间由本人验证密码直接恢复；曾有两位成员的空间必须双方同意。
- 恢复原空间、成员和业务数据，私密权限保持不变，回访日期不顺延，到期回访重新进入待办。原邀请始终失效。
- 恢复后再次关闭，生成新的关闭版本和 30 天保留期，旧关闭请求和旧申请不能重放到新一轮。
- 截止时间以服务器时间为准，到点即不可恢复。后台启动时及每分钟检查到期空间，自动删除其记录及子数据、邀请、申请、成员关系和空间；账号、个人头像及其他空间不受影响。

## 接口

所有接口均要求有效登录和已验证邮箱。关闭列表按关闭时间倒序，每页 20 项。

| 方法与路径（前缀 /api）                             | 请求                              | 返回                         |
| --------------------------------------------------- | --------------------------------- | ---------------------------- |
| GET /spaces/closed?page=1                           | 可选 page                         | items、total、page、pageSize |
| POST /spaces/:id/close                              | currentPassword、lifecycleVersion | 关闭空间摘要                 |
| POST /spaces/:id/restore                            | currentPassword、lifecycleVersion | ok、spaceId（仅原单人空间）  |
| POST /spaces/:id/restore-requests                   | currentPassword、lifecycleVersion | 含申请的关闭空间摘要         |
| POST /spaces/:id/restore-requests/:requestId/accept | currentPassword                   | ok、spaceId                  |
| POST /spaces/:id/restore-requests/:requestId/reject | 无                                | ok                           |
| POST /spaces/:id/restore-requests/:requestId/cancel | 无                                | ok                           |

摘要包含 id、name、lifecycleVersion、closedAt、purgeAt、members、canRestore、restoreRequest。成员仅含 id、关闭时 nickname、值为 null 的 avatarUrl；申请仅含 id、requestedById、status、createdAt、expiresAt。

无权限返回 404；状态冲突返回 409 和业务 code（SPACE_CHANGED、SPACE_EXPIRED、RESTORE_UNAVAILABLE、RESTORE_PENDING、RESTORE_CONFIRMATION_REQUIRED、RESTORE_REQUEST_EXPIRED）。密码错误返回 400，会话失效返回 401。密码操作沿用账号安全限流：每 15 分钟每账号 5 次、每 IP 40 次，超限 429。

业务读查询同时限定开放状态、实时成员关系及鉴权时空间版本。内容写入和邀请在事务内锁定空间，关闭、恢复、新绑定和清理采用同一事务机制。浏览器业务写请求携带 X-Space-Id / X-Space-Version；状态改变后旧请求响应不会重新填充旧页面。

## 数据与升级

SQLite 与 PostgreSQL 均新增增量迁移 20260907000000_space_lifecycle：

- Space 新增状态、生命周期版本、关闭操作人、关闭与删除时间。
- SpaceMembership 保存原成员身份和关闭时昵称快照，迁移从已有 User.spaceId 回填。
- SpaceRestoreRequest 保存申请及发起人认证版本；部分唯一索引保证同一空间最多一条 pending 申请。该索引由迁移维护，Prisma 模型无法直接表达。
- User.spaceId 继续指向当前空间；不调整历史密码、邮箱、记录或头像文件。

本地先备份原 SQLite 文件，再运行 pnpm run setup。测试均使用临时数据库，不会替日常数据库执行迁移。

生产在维护窗口内按 deploy/README.md 的升级流程操作：保存旧应用镜像与配置，完成数据库及头像成套备份，更新源码/升级包，运行 deploy/deploy.sh。增量迁移会先回填成员，再启动新应用；不要执行 reset，不要删除已有迁移历史。

完成升级后用两个测试账号验证关闭、记录隐藏、新绑定冲突、恢复申请和双方恢复，并检查 SPACE 生命周期数据已纳入备份恢复验证。单人恢复也应单独验收。

启用本功能后，不应直接回退到不识别成员表和空间状态的旧应用：旧版的新建/邀请会漏写成员关系。需要回退时进入维护窗口，使用兼容生命周期模型的修复版本；涉及数据库恢复时先核对上线后新增数据、关闭记录与删除截止时间。

## 清理与灾备

应用内清理失败后事务回滚，下轮重试；停机等待当前任务结束再关闭数据库。成功日志包含清理空间数量与耗时，失败输出重试提示，不记录纸条内容或密码。多实例重复清理保持幂等。

30 天指业务库保留期。既有数据库与头像灾备组继续按现有约 14 天策略淘汰（备份成功时执行）；部署者应保证备份任务持续成功，避免过期备份无限积累。产品不提供从灾备找回过期空间的入口。

灾备恢复前必须核对备份时间与后续关闭/删除记录；较早备份可能早于关闭操作。恢复后开放流量前检查空间状态与保留期限，并让启动清理完成，不能把旧备份作为延长产品恢复期的方式。

## 验证

API 测试覆盖关闭、恢复、期限边界、隐私隔离、申请角色、认证变更、新绑定冲突、并发、清理回滚与重启。迁移测试从旧版迁移历史创建已有账号及纸条，验证成员回填、内容不变与重复部署；SQLite 另验证备份文件恢复后的关闭状态和原成员关系。

浏览器测试覆盖桌面与 390px 手机、错误密码、键盘操作、双会话同步、迟到响应丢弃及 WCAG A/AA。独立 PostgreSQL 测试验证相同 API 流程与多实例事务；备份脚本及 CI 容器恢复检查同步验证成员关系一致性。
